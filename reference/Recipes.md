# Feature recipes

These are independent recipes. Select, adapt or omit them; none is a required world architecture.

**Narrative instructions plus AI-updated trackers.** A relationship, journal, outfit, reputation or story-preference tracker can update from the ongoing story without an explicit mechanical action parser. Explain what belongs in it, when to add/change/remove entries, and what should remain stable. Match structured entries by stable identity or names/aliases as appropriate, not a list position that may change. Provide a useful format example; sample data must not silently become real world facts.

**A situation followed by a consequence.** Situation-trigger effects follow story generation; guidance does not retroactively rewrite the scene that caused it. If a behavior must shape that scene, provide the rule beforehand in active instructions. Use triggerOnEvent for a narrative situation the AI recognizes, optionally AND a tracker/turn/prerequisite condition to narrow it. Situation classification is probabilistic; use explicit predicates only for requirements that genuinely need exact enforcement.

**A threshold or dependency chain.** A relationship threshold can unlock a new characterization block; a turn condition can introduce weather or a letter; a prior event can enable another event. Intentional one-shot/repeat flags and firedThisTurn scope matter. Check order where the later trigger reads an earlier result. Avoid requiring and blocking the same trigger.

**Choice/input plus later effects.** Present a selection or text form targeting a real tracker, then respond with a later ordered trigger. Correctly bound single-answer forms update immediately. Inspect binding after import; use current tracker data rather than initialValue from the live-world editor export.

**AI update buffer plus scripted merge.** The library's update trackers let the AI propose changed structured entries, while a script merges them into a persistent list. Root the buffer in a record (`entries: []`); list-rooted AI buffers lose updates, even with "append-only" wording. A record root can still jam: the AI may write rows as one nested list (`entries: [[…]]`), and a merge gated on `.entries.any(name.exists())` then never fires again. Gate on a non-empty inbox, drop or unwrap non-record items, and flag an inbox still full after the merge. Match records by identity and ask for complete entries: the buffer is cleared after each merge, so field patches have nothing to apply to.

**Conditional instruction content.** Use a native block-modification effect to add/replace/clear instructions. The source may be fixed text in the effect or text prepared in a tracker by an earlier script trigger. A script changes tracker values; the native effect changes the instruction block. Keep the block ID stable when disabling content so later re-enabling still targets a real block. A storyteller prompt field has no block to swap, but it can be one template line: set the evaluationRequest to `<<$eval_holder>>` and let option triggers rewrite that hidden tracker, so a player option swaps the whole evaluation prompt [PATTERN, one community world].

**Player-optional block, with no repeated writes.** The pattern in ../examples/optional-block.json:

1. A player-only text preference has initialValueBasedOnPC player, initialValue On or Off, initialValueChoices [On, Off], autoUpdate false. The player picks it at startup; later changes need the Storyteller-mode tracker editor.
2. A hidden non-AI-updated text tracker (hidden_boring in the example) records which choice has actually been applied. It is a cache, not another player preference.
3. A repeatable enabling trigger requires preference On AND cache not Enabled. It writes the enabled block content, then records Enabled.
4. A repeatable disabling trigger requires preference Off AND cache not Disabled. It writes empty content, or a deliberately chosen simpler fallback, then records Disabled.
5. Enable opening and later execution where needed. Initialize the cache empty so the selected startup choice gets applied. Once synchronized, neither trigger fires until the preference changes.

Clear with `content: ""`; do not delete the block. If the bundle also changes authorStyle or specialist rules, restore all of it to a coherent fallback (for Storymaster: ordinary narration, no Storymaster specialists or trackers).

Preference trackers can be hidden from the storyteller; triggers still read them. Tell the player the effect and turn cost, and never let an AI-updated tracker change the choice back.

**Rules, not code.** IW runs only native triggers and PawScript. Pseudo-code in instructions or a Give information effect (`character.flags['x'] = true`, `narrative.queue(...)`, `driftFromTag(outfit)`, hourly ticks, `{{bar:x}}` placeholders) is plain text the AI may or may not imitate: it sets nothing, and its variables don't exist. Every number a rule reads needs a tracker, every timed rule needs a trigger or a turn-counted condition, and a status line the AI writes needs a tracker or a plain-language instruction. State each rule once, in words.

**More exact mechanics when requested.** Script-owned numbers, independent prerequisite checks, a request-classification tracker or a controlled transaction may be useful for a precise system. If used, define who updates each value and avoid competing AI/script ownership of the same data. Check that every value a condition, script branch or template reads has a writer: a field the AI is told not to write and no script writes never changes, and everything that reads it is dead (a death trigger on a vitality nothing lowers). Freshness stamps are for consuming an AI-generated per-turn request, not for ordinary narrative trackers.

**Level-up menu.** An AI-updated XP number and a player-chosen threshold tracker. A repeatable trigger fires when XP is at least `$threshold` (a `$variable` requiredValue is read live [RUNTIME]), opens a single-select Present Choice whose `choices` is `<<$player.skills.where(value() < 5).keys().plain_list().title_case()>>`, so maxed skills drop out, into a hidden tracker, and resets XP. One repeatable trigger per skill matches that tracker, raises the skill with Change player skill (cap 5) and sets the tracker back to none. Match each condition to the exact text the menu shows for that skill (check it in the sandbox: multi-word skills come from slugs), and give every skill its own value: a copied condition makes one pick raise two skills and another raise none. Subtracting the threshold instead of resetting to 0 keeps overflow XP [PATTERN, one community world]. Let the player pace leveling by making the threshold a player_only number they may edit, show the current levels in the menu's message, and at the cap have a one-shot trigger rename the XP tracker ("MAXED") and hide it [PATTERN, one community world].

**Goal reached, game continues.** When the world's objective is met (a situation trigger, optionally narrowed by a tracker), one trigger shows a message, ends the game with continuation allowed (`effectEndsGame` true, see [Runtime](Runtime.md)), and replaces the route's instruction block with post-goal rules: what the player now controls, the new pressures, an open sandbox [PATTERN, one community world].

**Per-character thresholds.** When several NPCs each move along the same scale (corruption, trust, suspicion), give each NPC its own number tracker (or a script-owned record per NPC), never one shared number the rules read "per girl". One one-shot trigger per NPC and threshold (`triggerOnTrackedItem` at least 25, 50, 75) tells the AI what changes for that NPC from now on, or swaps in that NPC's next characterization block. One-shot is the right default here; endings that need all of them ("every NPC at 90+") become one PawScript condition [PATTERN; the parts are standard, the combination is not run]. When the premades are written in pairs and only one partner is in play, one AI-kept counter (times the partner used a power on the PC) can serve every pair with its own threshold per premade; add a Scenario as a second condition when the change should also wait for a story beat ("they have made up, but…") [PATTERN, one community world].

**Two meters decide a role.** For a path the player drifts into (hero or villain, loyal or rebel), keep two numbers and let a repeatable trigger on `A at least $b` set the role, objective or block for one side and `B at least $a + 1` for the other, so a tie keeps the current side and the two never both fire. A `$variable` requiredValue is read live, so the comparison follows both meters [PATTERN, one community world].

**Many attributes on one ladder.** When one NPC has dozens of trainable attributes (habits, looks, skills), give every attribute the same named tiers at fixed scores (for example 5 Habitual, 10 Reflexive, 15 Anticipates, 20 Escalates on her own, 25 Complete), each with one behavioral meaning, and give each attribute only a one-line ladder of specifics. The AI learns one rule, not dozens. Keep the numbers apart from a present-tense behavior snapshot that the narration reads, with anti-logging rules: no dates or past events, delete a lower tier's text when a higher one locks, one merged profile per domain. Render an attribute's ladder only while its score is above 0, after a one-line index of every key, so a fresh game doesn't pay for the whole table [PATTERN, one community world; gated billing RUNTIME].

**Attribute report, script ledger.** Don't let the AI keep many counters: it skips awards, misses a daily reset it judges from a free-text date, and stops moving them when it skips a tracker write, all silently when nothing reads the numbers back. Instead the AI rewrites a small ai_only report each turn, the story day as a number and up to a few keys from a fixed list that this turn trained (empty when none). A script after the updates adds 1 to each listed key not already trained today, clamps to the range, ignores unknown keys, clears the today-list when the day number rises, and refuses a day more than one away. Derive any global resistance from the scores (`max(0, 95 - total)`, or per domain) instead of decrementing it. A once-a-day gate keyed to an AI-written day opens on the sleep turn, from a report written before the morning is played: let the latest report of a day replace an earlier one. The script also writes a short AI-visible view of only the attributes past the first tier, each with its tier word, and on a crossing a one-turn line naming what to rewrite now ("reached 10: rewrite her figure in the cast tracker"), so the AI applies results instead of the tier table [RUNTIME for once-a-day meters on three NPCs, Dolphin, one world; the many-key version is a PATTERN].

**Player-introduced items stay as given.** In worlds where the player plants or gives an object that acts on NPCs (clothing, a charm, a potion), tell the storyteller the item keeps exactly the description the player gave: an NPC may refuse or store it, but never reskins it, shrinks its effect or turns it into a protection against the mechanic. Narrators otherwise shield NPCs by quietly rewriting the item [PATTERN, one community world].

**Closed magic.** When the premise has one supernatural source, say so and close the rest: the effect stays with whoever uses that source, does not spread to others, the house and objects have no will, there is no telepathy, and a character who believes in other magic is wrong. Without it, narrators tend to escalate the weirdness on their own [PATTERN, one community world].

**A belief until it is discovered.** For a hidden rule the player can find by trying (the spell can be made permanent after all; the device has a back door), key a lore entry to the mechanic's word with what everyone in the world believes, stated as fact ("cannot be made permanent, as far as anyone knows"). A situation trigger on the player attempting it gives the truth once, rewrites the lore entry to the truth, and an earlier near-miss trigger can hint that they are close. The secret costs nothing until it matters, and finding it is a lasting reward [PATTERN, one community world].

**Public text, secret effect.** For items the player buys or finds, give each one a public description (what the shop or label says) and a secret effect (the catch), and tell the AI that no character, label or shop ever states the secret: the player learns it by using the item. Items the player designs get a hidden catch too, chosen by the AI and recorded in Secret Info [PATTERN, one community world].

**A power with a budget.** A limitless power gives spectacle but no decisions. Give it two or three settings that trade reach, duration, side effects and how much attention they draw, a visible charge count with a cost per setting and a daily refill, and range and line-of-sight limits. Say that running out at a bad moment has real consequences [PATTERN, one community world]; the charges are AI-kept there, so a script-owned count (Attribute report, script ledger) is the safer build.

**Set-piece entrance.** For a boss or other big moment, a situation trigger on the threshold ("When the player opens the door to the boss room in the Verdant Temple") sends one Tell the AI what should happen next turn with the arena, the voice and the creature, ending in an instruction to close the page with a bold title card. That text lasts one turn, so keep a short standing note (personality, weak point) in the instructions or a keyword block for the rest of the fight. A second situation can hold the reveal back until the player acts. Describe what the player sees and hears, and leave their reaction to them [PATTERN, one community world].

**Escalation keyed to quest progress.** Tie the world's worsening to a Number count of the quest items (stones, seals) rather than to time, so exploring is never punished: non-repeatable triggers at `at_least` 2, 3, 4 and so on. Keep the count in a Number tracker: on a Text tracker only contains or does-not-contain applies, so a value written "1/5" contains "5" and fires the last step on the first item, and names ("Verdant Stone") fire nothing. Give information to AI is background for the turn it fires, not standing text, so let each step also replace a short World State block that lasts until the next step. Per-character change can use the same shape: an AI-updated Number and milestone triggers that each replace a stage block (the AI cannot count turns for "add 1% every five turns") [PATTERN, one community world; the Number and block mechanisms RUNTIME].

**Read the room before you escalate.** When a character pushes the story further (a game master, a tempter, an eager salesperson), give each push a story beat instead of a schedule: open with a small, deniable test (a list of dangers with one strange entry, an ominous line in a letter, a rumor), read the player's reaction, retreat with humor on a no, and go one step further on a yes. Routes that look ordinary can carry their own planned test scene. Put the step list in instructions and let the character choose the step; a script can cap the step (see Phase ceiling) [PATTERN, one community world].

**Narrator who is a character.** Tell the whole story as tagged dialogue (a game master and players at a table, a radio host and callers), with a control boundary: the narrator voices the world and every NPC, each player character is voiced only by its own speaker, and the player's character only by the player. Give the narrator a goal and the audience a story of its own (the people at the table), and list the valid speaker tags once. Every example must use exactly those tags, since examples are what the AI copies [PATTERN, one community world].

**Secret Info by layer.** When a world has two kinds of hidden knowledge (the story and the frame around it; the mystery and the people's motives), ask Secret Info for two short labeled paragraphs, each forbidden to mention the other's subject. Planning stays separate and neither layer crowds out the other. Keep both short: Secret Info bills as output and again in Short Term Memory [PATTERN, one community world].

**Routes to a fixed beat.** To steer without railroading, have Secret Info name the beat the current scene should land on, then three to five routes to it (one a wildcard), each suited to a different kind of player action, and mark the route that happened. Next turn the narrator plays the route that fits what the player did, bending it rather than playing it as written, and the destination holds. Queued next-turn actions for up to four NPCs (what each wants here, what they do about it) and a one-line "forbid" (what must not happen this turn, and whether it held) fit the same section. A custom evaluationRequest can reprint the plan before judging the action. It costs output each turn and again in Short Term Memory until summarized [PATTERN, one community world].

**Standing NPC plans.** To make named NPCs pursue their own goals, push back and act behind the player's back, keep one short block: every turn Secret Info holds one or two sentences per named NPC (what they want now, what they will do next to get it, and where that differs from what the player wants; "cuts against" makes every plan adversarial), written from that character's side and from what they can know; each plan is carried forward as written until the story gives that character their own reason to change it, and an NPC who is off-screen is doing something. Open the descriptionRequest by having each character act on the plan recorded on earlier turns and keep at it when the player wants otherwise, and have the summaryRequest keep each character's standing intentions and grudges so plans survive compression. Optional: an evaluation line that rates persuading someone against their personality as very hard, and personality presets that give each NPC something to want. It is the core loop of SelfB's Naughty Claude without Storymaster's planning layer: about 1.5k of instructions and about 250 characters of Secret Info per NPC a turn, which bills as output and again in Short Term Memory; names in it activate lore [PATTERN, one community world; not run on Dolphin].

**Subplot rotation.** Keep the running subplots in one ai_only tracker (3 soft, 5 at most), each with `state` (facts, never prose), `next` (the waiting situation, never an instruction), the turn last advanced and `pull` (evidence the player cares: "asked about the sister twice"). A template in the evaluationRequest names this turn's subplot, picked at random from those not advanced last turn: `<<first_available($threads.items.where(name != $threads.last_advanced).random().name, "none yet")>>`. The narrator may follow the player instead when they have moved toward another thread three turns running. Close a thread with no pull for 10 turns. Start the list empty rather than with a blank entry, or the first pick is a blank name [PATTERN, one community world].

**First sentence last.** End a custom evaluationRequest by having it write the scene's first sentence: something physically present (an object, a sound, a smell), no clock, no "as you", no phrasing from the last two turns. The narration then continues from it. It aims directly at the same opening, turn after turn [PATTERN, one community world].

**Fixed-role option slots.** Fix what each suggested action is for: option 1 the responsible choice, option 2 the indulgent one, option 3 skip to the next story beat, all in first person and drawn only from what the outcome text shows. Players learn where to look, and the skip slot keeps a slow scene moving [PATTERN, one community world].

**Section-header triggers.** In a long trigger list, add triggers with no conditions and no effects named as dividers ("==== Game options ====", "=== Store ===") to group the list in the editor. They never fire and cost nothing [PATTERN, one community world].

**Identity anchors through transformation.** When a cast is remade again and again (new bodies, outfits or species each chapter), give each person a few fixed markers that never change: a signature color, a token they always wear, a stage name. Require every new look and outfit to carry them, and name them in the cast tracker. Narration and pictures then keep track of who is who after each change [PATTERN, one community world].

**The mind bends the action.** When the PC's mind is changed (an intelligence drop, a new want, rising arousal), keep each part in an AI-kept tracker and template them into the evaluationRequest, which first rewrites the player's action into what that mind would actually attempt now (simpler for a dulled mind, pulled toward the current want) and then judges it as usual; template the same trackers into the descriptionRequest so narration and inner voice agree. The player keeps typing freely and the change shows in what the PC does, not only in how it is described. Give each mind tracker a short fixed ladder with stated ways down [PATTERN, one community world]; how far the rewrite strays from what players intend is not measured.

**Off-screen cast vignette.** To keep a large cast acting on its own, ask the description instructions for a short titled second section each turn (about 120 words): a scene between two other characters, away from the player, pursuing their own plans. Name the moments when it must happen in the player's room (contests, ceremonies, required sessions) so the main events stay shared. It costs a fixed slice of output and shows the player schemes they would otherwise never see [PATTERN, one community world].

**Cast by venue.** For a written cast in a city, one block lists each venue (short codes) and each named character with a primary and a plausible venue, plus "use established characters before creating anyone new" and who to cast in common roles. The right people then turn up in the right places without lore or scripts [PATTERN, one community world].

**Peanut gallery.** Give an antagonist an audience that eggs them on but can never act: an online group chat in a tracker the AI clears and refills each turn with a few lines, a block that says who they are and what they push for, and a hard rule that they are remote spectators who cannot touch the world. It adds outside pressure and, when the chat is shown to the player, a window into the antagonist's next move [PATTERN, one community world].

**Consistency alarm.** For a premise fact the AI keeps getting wrong (everyone here was once a man; the town has no magic), add a repeatable situation trigger that recognizes the wrong version in the story and sends Tell the AI to correct it, naming the tracker to repair. It follows the turn that went wrong, so also state the fact in standing instructions [PATTERN, one community world; whether the situation is recognized not measured].

**Time and location: a soft default.** Offer the sample's Time and Location (whereWhen) block unless the premise makes a clock/location header unhelpful. It helps chronology and orients the player. Adapt the geography, calendar and precision to the setting; omit irrelevant levels rather than inventing a country or continent. Put exactly one header at the beginning of outcomeDescription, not a second competing heading.

**NPCs, keyword blocks and always-on blocks** are chosen by intended activation; see [Characters.md](Characters.md#keyword-blocks).

## Dynamic content

Text installed by a block-modification effect is a snapshot of its `<<...>>` values; the ways to keep a value live are in [Runtime.md](Runtime.md#template-interpolation-runtime). A block reinstalled every turn freezes values when its trigger runs, so values set by triggers below it arrive a turn late: order producers above the installer, or use `<=...=>`.

**Player-selected layered openings.** Combine independent choices into meaningful variations using ordered text replacements, then install the result as background. This avoids authoring every full combination; keep fragments compatible and add combination-specific handling where needed. See [layered opening](../examples/recipe-layered-opening.json).

**Premade installs its variant.** When premades belong to different settings (regimes, factions) or come in linked pairs, keep a short line on every variant in the main instructions and one empty block; each premade's start trigger fills the block with its own variant in full, or with its partner's attitude and a discovery scene, and swaps the background. Only the variant in play bills [PATTERN, one community world].

**Opening menu with a random pick.** On turn 1, a Present Choice offers the openings that fit the chosen antagonist or premade, each with its own Tell the AI trigger on the choice tracker. A "Random" answer runs a script: filter the eligible openings from a hidden YAML table to those flagged `random_ok` (skip openings that need further player input), roll a weighted pick over a `weight` field and write the code to the same choice tracker, so the hand pick and the random pick share one dispatch [PATTERN, one community world]. `effectFireRandomTrigger` is the unweighted, script-free version.

**Time-boxed directive.** For a directive that should bill only while its arc lasts (the antagonist's opening agenda, a tutorial voice), render it with one template line, `<<if($arc = "initial", $agendas.where(code = $opening).first().text, "")>>`, and let a turn-N script (or a beat) set `$arc` to "over". The text stops billing with no block swap [PATTERN, one community world].

**Pick N companions.** A start Present Choice (multiple selections, exactly N) writes the picks into a hidden list; the opening and the instructions read `.item(1)` to `.item(N)`, and the candidates not picked stay in the world as ordinary characters [PATTERN, one community world].

**On-demand generation with retained results.** Install a substantial generation brief only when needed, store a compact result, and clear the brief after a matching completed request. Do not clear merely because a turn elapsed. Prefer infrequent event-driven requests; retained tracker context and AI updates can outweigh the omitted instructions. See [on-demand generation](../examples/recipe-on-demand-generation.json).


**Scene-gated sections.** For large reference text (creature guides, image rules), keep one always-on block and wrap each section in a live `<<if(flag, '…', "")>>`. A straight `'` inside the section, even in "subject's", ends the string and the section never renders: write ’ or reword. A script high in the trigger list sets the flags from scene state, for example AI-written tags matched against synonym lists in a hidden tracker, with a cap on how many count. Only rendered text bills, at the full instructions rate; a false section costs nothing [RUNTIME, Dolphin]. Gates read the previous turn's end, so check turn 1 against the start-of-game state: default-on gates or a "load everything" seed make the opening expensive. `try($scene.flag, true)` fails open (no scene data loads everything); `try(…, false)` fails closed. Choose per section.

**Lookahead.** Also gate on an AI-written list of who or what is expected next turn. For an unannounced arrival, tell the narrator to end the turn on the arrival and describe them next turn.

**Self-configuring setup.** A hidden tracker with empty fields. A start-of-game trigger copies any author-filled fields to a hidden seed, then sets the tracker ai_only with updates on; its update instructions say fill only empty fields, once. The AI fills it on turn 1 [RUNTIME, Dolphin]. A mid-game Keep trigger (turns 1–3) restores seeded fields; a one-shot Lock (all filled, or turn 3) hides it with updates off. Blocks read it by template, so it bills once, as instructions. The same start trigger can ask for a whole timetable: the PC's weekly schedule and the main NPCs' schedules into trackers, with the setting's timetable rules (class lengths, travel time, clubs) in a block, so people are where they would be [PATTERN, one community world].

**Offstage archive.** A script moves records of characters unseen for N turns (script-set lastSeenTurn) to a hidden tracker and restores them when the name returns in an update or the lookahead list. List archived names in the update instructions by template so spellings are reused.

**Place archive.** For places the player returns to, keep the current place in one ai_only record (look, people, laws, open plot) and the rest in a hidden archive keyed by a place key the AI writes. Each turn a script compares the key with last turn's: on a change it files the record under the old key, then restores the new key's record or starts a blank one. A stage flag set from which fields are still empty picks a one-turn instruction ("now write the look", "now write the people and laws", "returning after N days"), so building a place spreads over turns with no long always-on rule. A move the AI never writes into the key is invisible to the script, so keep that rule short and loud [PATTERN, one community world].

**Per-place picture style.** The image-style wrappers (imageStyleCharacterPre/Post, imageStyleNonCharacterPre/Post) can be templates reading a tracker, so a script can change the look. On arrival the AI writes a style family and short look slots (medium, artists, palette, lighting); a script compiles them into the wrapper text and archives them with the place [PATTERN, community worlds; styles changed per place in play].

**Pre-seeded archive.** For a written cast, start the archive with each person's full record (per player character if circles differ); the restore step brings each in on first appearance. Hidden, so free until then; the same looks on cards bill as LTM every turn under v4. Add "never create an entry for anyone listed" [PATTERN, one community world].

**Large library, drawn by template.** Keep hundreds or thousands of items as records in hidden YAML trackers: hidden values are not sent, so storage is free. An always-on block draws with `$lib.random(n).format_each("…").join("\n")`, and only the drawn lines bill. A template draw re-rolls on every render, so store it. Prefer a script: when a restock signal changes (a day counter, a button flag), a trigger writes the drawn names to a hidden tracker and the block lists `$lib.where(name in $drawn)`. If the AI copies the names instead, a retyped name drops out silently, an empty copy redraws next turn, and the new draw shows a turn after the signal, and a player-visible holder shows the secret names: keep it ai_only [PATTERN, one community world; failure modes read from the file, not measured]. For effects that accumulate (curses, mutations, upgrades), append each drawn code to a hidden per-target applied list by script and render only `$lib.where(code.in($applied)).directive`: a catalog of dozens of effects then costs only what has landed. Roll a variant at draw time (a hidden index picks `BD02A`, `BD02B`…) so random details are never the AI's choice, and let the script that applies an effect remove its opposite [PATTERN, one community world]. For a configurable cast, premade dropdowns pick a code and each cast block is one line, `<<first_available($cast.partners.where(code = $config_partner).first().text, $cast.partners.where(code = "none" and pc = $pc_key).first().text)>>`, with a fallback per premade; after setup the dropdowns go player_only and stop billing. The same library can serve two roles (an antagonist package reused as a companion in another mode) under a preface telling the AI to treat the other framing as background only [PATTERN, one community world].

**Player-directed draw.** Before a random draw, offer a menu: leave it to chance, draw from a pool I tick, choose the items myself, or stop asking. The pool and pick screens are Present Choice effects whose `choices` is a template over the eligible rows (`<<$lib.where(code none in $used).format_each("{label}").join("\n")>>`); the draw script reads the ticked labels. Players who want control get it without a second world [PATTERN, one community world].

**Roll the count and the draws together.** To get a random number of random results without a script, a Tell the AI effect rolls both when it fires: "spins this time: <<1d2 + 1d2>>; spin 1: <<1d13>> … spin 4: <<1d13>>; use only the first X". The AI only looks the numbers up and shows them in a fixed format ("never describe a result as fitting or chosen"). Carry the table in the same text or an always-on block: a keyword-keyed lore entry may not be in front of the AI on the roll turn [PATTERN, one community world].

**Catalogue by message, unlocked in tiers.** Show a store or catalogue to the player with Show Message when they ask for it (a situation trigger), formatted for reading, and give the AI only a short Give information on what was shown. Unlock further tiers on request or by a count (items bought), let a start dropdown ("I have done this before") give returning players a fast path, and have each unlock rewrite the AI's item block to include what is now on sale, so the rules grow with the store [PATTERN, one community world].

**Written hooks times modifiers.** Draw one concrete, scene-shaped entry per source per day, then stack small modifier sets on it: a player-picked setting, a drawn modifier, a stocked extra. The entries hand the narrator scenes; the modifiers keep repeats apart [PATTERN, one community world].

**Plan before the reveal.** For a cycle with a hidden program (a week's theme and contests, a dungeon's floors, a heist's twists), have the AI fill a whole plan sheet in an ai_only tracker at the start of the cycle, before any character announces it, then append results as they happen. A committed plan keeps several turns of narration consistent with what was promised. Clear or rewrite it at the next cycle start [PATTERN, one community world].

**Items that remember an owner.** A changed item records its owner: the owner using it gets the effect, anyone else becomes like the owner plus the effect, an ownerless one gives the plain effect. A few uses each (rolled by template, recorded once) spread an effect through a household [PATTERN, one community world].

**Rules gated on what is present.** Render each category's rules only while one of its items is in play, `<<if($dolls.any(name in $present), "DOLL RULES…", "")>>`, and a combo line when two categories are both present. Rules for an effect that outlasts its item must also be gated on that effect's state, a progress tracker or the name in an effects log, or they leave with the item while the effect runs.

**Setup dropdowns with a Custom checklist.** Player-chosen dropdown trackers (initialValueChoices, initialValueBasedOnPC player) are read by templates and Start triggers; compare each with its exact choice strings. A Custom choice opens a multi-select Present Choice into a hidden tracker; start each line with a unique prefix ("Angels:") and test `$picked contains "Angels:"`, checking no prefix appears inside another line. The AI needs only the rendered consequences, so the dropdown trackers can be player_only.

**Player-chosen cost options.** Offer the expensive extras as player_only dropdowns at character select. Start-of-game triggers read each one: install the block or swap descriptionRequest when chosen, hide and switch off the tracker that serves it when not, then hide the dropdown itself. Hidden trackers and empty blocks are not billed, so an unchosen extra costs nothing; tell the player what each choice adds per turn. The same triggers can hide trackers that only one starting route uses. Use the player-optional block pattern above instead when the choice must be changeable mid-game [PATTERN, one community world; hidden-tracker billing RUNTIME].

**Route board that loads one plan.** Offer several routes (jobs on a board, invitations, cases) as one-paragraph teasers in a short always-on block. When the pick is recorded, one trigger per route replaces the board with that route's full plan, hidden twists included, so only the chosen route is ever sent. Make the pick robust: a dropdown or Present Choice, or an AI-written value with an enforced format, matched on the route's name as well as its code, since a free-text "contains Q2" never fires on "The Siege" [PATTERN, one community world; the robust pick is a design response].

**Next route as the post-game.** When a route ends, mark it done, restore the board without it (repeatable triggers), and start the next one with the history kept. The post-game is then the same game with a new route, not a cut-down sandbox [DESIGN RESPONSE, untested].

**Episode dossier and lifecycle.** For a game of repeated self-contained episodes (haunted sites, heists, cases), give every episode the same dossier shape in lore and in the instructions: entry condition, hook, three to seven rules, cast with roles, hidden truth, escalation, a clear condition that is a testable action ("has answered the phone behind the counter"), not a mood, and reward. Key each written dossier on its title, so a first action that names it (`choose(random_between(1, 3), …)` in firstInput) loads it that turn; the AI invents later episodes in the same shape. One ai_only tracker holds the live episode: the AI writes title, objective, clear condition, cast, `rules_hidden` and `rules_known` (a rule moves the turn the character learns it) and a stage; scripts own the counters. A PawScript-condition trigger on stage `entry` resets the counters and installs an episode block whose live templates show "rules known 2/5", the known rules and the clear condition; one on the end stages pays out, resets and empties the block. Handle every end stage (cleared, failed, abandoned), or a failed episode never closes and the next one can't start [PATTERN, one community world; the failed-stage handling is a design response].

**Code-to-prose compiler.** When the AI must describe many new characters consistently, have it write one short coded line per character (pipe-separated slots: gender, age, height, build, hair, eye color, personality scores, talkativeness), then a repeatable script expands the codes into the long appearance and voice text, picks personality traits as the nearest profiles from a hidden library, and blanks the codes. Tell the AI never to describe what the compiler writes. Tier the records (passing, recurring, core) and prune passing ones a few turns after last seen. The compiler's words reach every picture prompt: keep its body text fitted to the world, and give characters under 18 no body clause at all [PATTERN, one community world; the age floor is a design response].

## Turn-state patterns

Optional patterns; trigger order is execution order.

**Script calendar.** The AI writes only the story date (`2055-10-12`). A script after the updates refuses a date earlier than the last, appends `$d.format_date("weekday")`, counts days from the first date, and writes a strip of nearby dates (`Tue 12 Oct (TODAY) · Wed 13 Oct · …`) that a block shows; the narrator takes weekdays and day counts only from it, since AI-kept counts drift [PATTERN, one community world: 40 turns, no wrong weekday].

**Script-awarded achievements and tips.** A script computes each achievement from state, adds new ones to a player_only list and states them in a one-turn beat for the AI to voice; say it awards no others, or it invents some. One-shot tips work the same way: (condition, message) pairs, at most one a turn, each once, spoken by a character [PATTERN, one community world].

**Previous-value snapshot.** The last trigger (always true, repeat) copies watched values to script-only trackers: `$prev_lp = $lifepoints`. Triggers above it read this turn's change, such as `$lifepoints < $prev_lp` for a spend. AND a delta with an event condition when the story and the number must agree. Clamps (a maximum loss per turn) also go above the snapshot.

**One-turn AI write window.** To let the AI rewrite a locked tracker once, a trigger switches its automatic updating on (optionally with new update instructions), stamps `$window = $game.turn_number` and tells the AI what to write. A relock trigger ordered above it, on `$window > 0 and $game.turn_number > $window`, switches updating off and zeroes the stamp. A mid-game switch applies from the next turn (a start-of-game one is live on turn 1), so the AI writes exactly once, on the turn it receives the instruction. Keep the switch out of triggers with Request Input.

**Player-checked day record.** At each story-day boundary, open a one-turn write window on a hidden draft tracker (made visible and updating for that turn) asking for a bounded record of the day: at most 12 lines, one plain sentence each, who did what with whom, fights, confessions, deals. Next turn, or after a few turns if nothing came, a script files the draft into that day's visible tracker, adds the facts the script owns itself (the choices, the rolls), hides the draft again and shows a message asking the player to correct the record. Describe the day trackers as "checked and corrected by the player, so treat it as what happened". The player owns a memory of the story that summaries can't blur; a few day records bill as tracker values every turn [PATTERN, one community world].

**Periodic AI updates.** Unlock a large, slow-changing tracker on `$game.turn_number % N = k` and relock on `% N = k + 1`; it is rewritten one turn in N.

**Cooldowns.** Stamp the turn in the effect and gate on `$last_x <= 0 or $game.turn_number > $last_x + 3`. A very large stamp disables the trigger for good.

**Rising-chance timer.** For an event that should grow more likely the longer it hasn't happened, use a repeatable trigger whose random chance is an expression on a since-last-event counter (`1.25 * $turns_since_change` percent). The pressure builds with no fixed schedule. Let the same trigger reset the counter when it fires, rather than leaving the reset to the AI [PATTERN, one community world]; the trigger reset is a design response.

**Repeating milestone.** For a reward every N points of a running total, one repeatable trigger on `total at least ($count + 1) * N` that adds 1 to `$count` replaces a ladder of fixed thresholds. Read the all-time total, not a spendable balance, and add guards (a cooldown, "not in the middle of a scene") as further conditions [PATTERN, one community world].

**Per-turn verdict tag.** An AI-updated text tracker asks for tags judging only this turn, or None. Text-contains conditions react to each tag, and a last trigger resets it to None (copy it first to keep a record). Tags stay turn-specific; the classification is still the AI's judgement.

**Scored event codes.** For a mood, favor or reputation that must move at a steady rate, don't let the AI keep the number. It writes this turn's events as codes from a fixed list (RUDE, KIND, REFUSED, BORING), or leaves the field blank; a repeating trigger on a non-empty field applies a fixed weight per code, clamps, clears the field and writes one of a few band paragraphs into a block (perks that grow and shrink, a warmer or colder voice). The AI never sees the number. Scripts can add codes of their own (a refusal the resolve script detects). Start the score in the middle of its starting band, or the first event of any kind installs the next band's text [PATTERN, one community world].

**Situation catalog.** For more situations than the editor's ten Scenarios, or ones a script adds mid-game (dynamic Scenarios no longer fire), keep an AI-visible, read-only YAML catalog (`id: {when: …, once: true}`) beside a per-turn tag tracker for the ids whose `when` happened. One trigger per id reacts to its tag; the last removes used one-shots from the catalog and clears the tags. Triggers must exist in advance; a script-added id wakes its dormant trigger. Bare id lists (`[]`), record roots and text tags each landed every id on 10 of 10 turns [RUNTIME, Dolphin, one run]. Use lowercase ids that don't contain one another. Mis-tags burn one-shots, so script what must be exact. The catalog's `when` text bills every turn. Adapted from a [community wiki design](https://infiniteworlds.mywikis.wiki/wiki/Morwen%27s_Situation_State_Machine).

**Wait for a well-formed write.** Gate a follow-up on the shape of an AI-written value (contains `(`, no longer contains the placeholder), not mere change, so a malformed write just waits.

**Append-only ledger.** For a log the AI keeps (edits made, deals struck), use a YAML list of records with fixed fields (`editor`, `target`, `change`), append one when an action starts, never rewrite a record, and write a reversal as a new record. No status fields means nothing to drift, and the history survives [PATTERN, one community world].

**Offer and answer protocol.** For a choice the AI must put to someone and then record (a deal, a vote, which curse goes to whom), switch on two request trackers when the offer is drawn: a presented flag the AI sets when it actually narrates the offer, and an answer limited to a few exact strings (`A:SLOANE,B:BROOKE`, `REFUSED`, `LAPSED`). A lock trigger copies the answer the moment it appears; a stamp trigger records the turn and story hour of the presentation. Honor an answer only on a later turn than the presentation (two turns on the player's own choices, so the AI can't answer for them), a refusal at once, a lapse after a story hour, and an untouched offer at the next morning. Press with Tell the AI if nothing is presented after two turns, and switch the request trackers off on resolve. To keep scheduled offers out of the night, map an hour counter to a clock hour: `(18 + $hours) % 24` for a story that starts at 6 PM [PATTERN, one community world].

**Per-model text.** `$game.ai_model` returns the display name (`Dolphin`, `Smilodon`) and text `=` is case-sensitive. Templates in a tracker's own update instructions are evaluated live, so `<<if($game.ai_model = "Dolphin", "…", "…")>>` there selects per model. Blocks can use selectedAIProfiles instead.

**Start-up codes.** A player-only text tracker at character select holds typed codes; one one-shot Text-contains trigger (case-insensitive) per code applies each. List the codes in charSelectText. To make codes switchable mid-game, use repeatable triggers per on and off value, each installing or emptying its block, with a trigger blocker so the on and off triggers never fire on the same turn, and tell the player they may edit the tracker at any time [PATTERN, one community world].

**World-stats markers.** IW's creator stats (stats page and CSV) list every trigger by ID with Games and Fired counts, so one-shot triggers can report which settings players pick and how far games get. Add a hidden Number tracker (`stats_markers`, 0) and non-repeatable triggers whose only effect is the script `$stats_markers = $stats_markers + 1`, named to sort together ("Stats: Pace = Fast"). Mark each option of a setting the player picks, at start of game and mid-game (`$pace = "Fast"`, exact and case-sensitive; `$themes.contains("Cats")` for a multi-select, with no option inside another); milestones with `>=` so a jump still counts (`$day >= 3`); turns (`$game.turn_number >= 25`); and the model (`$game.ai_model = "Dolphin"`, plus an Other marker that is `!=` every listed name). Always add "Stats: Started" on a condition that is always true: the stats' Games total also counts older versions and saved copies, so Started is the denominator. A trigger rebuilt with a new ID starts a new row, so keep marker IDs fixed across versions. Hidden values are not sent, so markers cost nothing. A zero is usually unreached or unpicked; check "How far they get" first [PATTERN, one community world; per-ID counting RUNTIME].

**Due today.** An AI-kept roster with a weekday field; a block lists `$roster.where(day contains $weekday or day contains "Daily")`, the weekday computed from the day counter with `choose()`. The AI keeps the roster, the template decides who turns up [PATTERN, one community world; an AI-kept day drifts, see Script calendar].

**Daily NPC roll.** While a daily field is `none`, a template rolls and `choose()`s a trick; the AI records one line, or `quiet`, which then renders all day. An unrecorded miss re-rolls every turn, so store the roll by script or require `quiet` [PATTERN, one community world].

**Computed stamps.** Render the number the AI must copy ("end today's lines with (ends day <<$c.day + 7>>)"), so expiry is copying, not arithmetic [PATTERN, one community world]. For effects with a stated duration rule (3 minutes per year of the caster's age), keep each running effect with its end time in one list and have the descriptionRequest expire effects against the clock each turn; render the end time from the rule rather than leaving the arithmetic to the AI [PATTERN, one community world].

**Trigger-owned duration.** When an effect becomes permanent after N turns in a state (locked in, cursed, worn), let the AI report only the state (yes or no) and let a trigger count: a repeatable trigger adds 1 to a hidden number each turn the state is yes, another resets it to 0 on no, and a one-shot trigger at N shows the player a message and tells the AI the effect is now permanent. The threshold never depends on the AI counting turns [PATTERN, one community world].

**Fixed cycle with a skip.** For a schedule that repeats (a week of a game show, a school term, a festival's days), write each day's beat once in the instructions and keep the current day and the next major event in trackers; a visible one-line "next event" lets the player type Skip, which the evaluation or a trigger turns into a montage to that event. Let a script own the day and the cycle count (an AI-kept day drifts, see Script calendar), and if the AI writes the day, list every value a trigger waits for in its description. Send the day's reminder once, from a trigger that rewrites a short Today block, rather than a repeating Give information, which re-sends every turn and lasts one turn. Give every way of losing the cycle an ending, and rules for the last rounds when too few remain for the normal procedure [PATTERN, one community world; the script-owned parts are a design response].

**Blackout with a picked outcome.** A one-time offer (lend the body, take the pill) ends the turn on a setup line with nothing narrated; accepting fires a Present Choice of outcome flavors; each answer's trigger tells the AI to skip days, quietly update the changed traits, and open the next scene mid-action with clues of the lost time and a late reality check. The player chooses the flavor of a change they did not see happen [PATTERN, one community world].

**Decaying novelty list.** For new sensations, injuries or habits that should fade (long hair on the neck, new shoes, a fresh tattoo), keep an ai_only list of entries with a cause, what is felt and hours left, templated into the turn instructions so the narration mentions them unprompted. Let the AI only add entries; a script counts the hours down from the story clock and removes an entry at 0 or when its cause is gone, since an AI countdown has to rewrite every entry each turn [PATTERN, one community world; the script countdown is a design response].

**Phase ceiling.** For a story that escalates in phases across sessions or chapters, a script advances the session every N turns (a hidden turn count; the AI never counts) and sets the highest allowed phase from it, shifted by a route or a pace dropdown. The phase block renders only that phase's text (a live `<<if>>` on the phase), and the narrator still decides whether to reach the ceiling. A one-turn Tell the AI near each session's end lets the narrator close the session in the story [DESIGN RESPONSE, untested; gated text bills only when rendered, RUNTIME].

**Dice the narrator can fudge.** Name four outcomes: Success, Failure, and Success or Failure "(Fixed)", where the narrator quietly overruled the dice; fixed results are always played as real and logged in Secret Info. To make the dice real, a script rolls the next few d20s into an ai_only tracker each turn and the rules say how a skill becomes a modifier; a player_only log of the real rolls lets the player catch a fudge [PATTERN, one community world; the script dice are a design response].

**Dread clock.** For episodes that should grow more dangerous the longer they run, a script counts turns inside the episode and compares them with a soft and a hard budget set by the episode's class (12 and 14 turns for the easiest), adding pressure past the soft budget and a jump at the hard one; a script-counted rule-breach term can add to it. Bands of the result fire one Give information beat each, once per episode (flags reset at the episode's start), from "the place has noticed you" to "terminal pressure: force the choice in two or three turns". Give every episode class its own budget [PATTERN, one community world].

**Pressure die.** A real roll in a custom evaluationRequest (templates render there) can set what the world does around the player, separate from whether the action succeeds: `The die came up: <<1d10>>.` with bands 1-2 one thread loses pressure, 3-6 the world holds, 7-9 one thread advances faster than expected, 10 something arrives early from a direction the player isn't watching. Quiet turns then happen by dice, not by drift [PATTERN, one community world; templates in evaluationRequest RUNTIME].

**Drawn transformation ladder.** For a slow change the player earns by exposure (contamination, corruption, a curse), keep a script-owned value fed by an AI event log (value and reason, summed and cleared by script) with named stages. At each threshold a one-shot script draws a hidden type from a list (wolf, moth, salt, static), then visible features from small lists, and a Tell the AI turn says how to show it ("don't name the shape yet; show the first symptom; an NPC notices"). Each game becomes something different, and the AI never chooses the outcome [PATTERN, one community world].

**Ordinal words.** `choose($e.intensity.lower(), "slight", 1, "mild", 2, "moderate", 3, 0) < 3` compares a word scale, for example to raise an entry to a minimum without lowering it.

## Request and commit example

In [recipe-request-commit.json](../examples/recipe-request-commit.json), the AI records the current requested event and turn stamp. The first trigger resets the receipt, not the unconsumed request. A later trigger checks freshness, then checks funds/ownership and commits a purchase or rejection. A following effect displays the receipt and clears the request; the receipt remains for next-turn continuity. Narration describes an attempt until the committed result is available. A freshness stamp prevents stale reuse, not incorrect classification. The updater records the scene, not just the request: it logged narrator-invented actions as the player's until told to judge that field only from the player's own action text this turn (fixed on Dolphin). This pattern is optional: native choices, thresholds and timed effects do not need an AI request layer.

The [example index](../examples/index.json) records each complete world's purpose and verification scope. [Payloads.md](../examples/Payloads.md) supplies smaller native shapes. Remap IDs when combining worlds and validate the result.

## Guarded state patterns

Optional complete worlds built from known primitives; do not impose them on a world's design.

| Example | Intent and boundary |
| --- | --- |
| [Completion and award](../examples/recipe-completion-award.json) | Set Award state's ready field to 1 through an authored action. Commit the score and completed flag together; trigger firing alone is not successful completion. |
| [Candidate acceptance](../examples/recipe-candidate-acceptance.json) | Keep candidate and accepted records separate. Set submitted to 1 to request acceptance. Checks identity, required field existence and quantity bounds before locking. A small semantic gate, not a YAML type validator. |
| [Archive and restore](../examples/recipe-archive-reactivate.json) | Set Active record's request to archive or restore. Copy selected fields explicitly and consume the request. Whether an archived record reaches the AI depends on the tracker's visibility. |
| [Cached random](../examples/recipe-cached-random.json) | One trigger samples once and both blocks read the stored roll. Before that trigger runs the initial value is 0; reset ready to 0 only when a new draw is intended. The roll is available to narration from the next generation. |
| [Consumed milestone](../examples/recipe-consumed-timer.json) | Increment turn time before checking ticks >= 3; consume the crossing once. This counts ordinary eligible trigger cycles, not elapsed story time. |
| [Choice domain](../examples/recipe-choice-domain.json) | Accept only Courier or Archivist at consumption. Blank offers the form again; unexpected manual/script values do not commit. Multiple selections need their own delimiter/representation validation. |
| [Compiled plot](../examples/recipe-compiled-plot.json) | Literal Scenarios with ordered prerequisites and guarded awards. See the plot compiler in [tools/Usage.md](../tools/Usage.md#plot-compiler). |

The validator's review advisories are prompts to inspect intent; an existing guard can trip one (see [tools/Usage.md](../tools/Usage.md)). Choice menus and Enforce format do not validate manual or script writes.
