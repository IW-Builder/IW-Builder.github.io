# IW-Builder roadmap

Updated 2026-10-24 for kit 1.4.0. This public roadmap describes delivered capabilities and useful future work. It is not a promise of platform coverage or a release schedule.

## Available now

- **Authoring reference:** consolidated behavior, editor/UI workflows, consistent user-facing terminology, and a concise catalog of identified trigger conditions and effects.
- **Validation and import diagnostics:** native export compatibility checks, named reference diagnostics, conservative static advisories, and read-only source/import comparison.
- **Story tools:** source-preserving extraction with reviewed boundaries, explicit branch identity, conflict rejection and integrity manifests.
- **Browser harness:** dedicated-browser connection, rendered-page capture, refresh-verified editor export, backups and offline integrity inspection. Authenticated capture/export is verified; automatic gameplay and server persistence are not implied.
- **Reusable examples:** completion and award guards, candidate acceptance, archive/reactivation, cached randomness, consumed timers and choice-domain checks. Native startup payload examples also cover background, first action and Other Character Add/Modify/Delete, with explicit runtime limits. Exact compositions are structurally checked patterns, not individually certified gameplay.
- **Plot compiler:** literal-Scenario prerequisite graphs with dependency ordering, guarded awards and structural reachability. Connectivity does not prove narrative satisfiability.
- **Distribution:** browser checker, individual references, combined text editions and a hashed downloadable package built from shared sources.

See [Engineering tools](Engineering-Tools.md), [Story tools](Story-Tools.md) and [Recipes](Recipes.md) for usage and scope.

## Future work and prerequisites

| Area | Useful next step | Required evidence or capability |
| --- | --- | --- |
| Runtime state and prompts | Clarify character-record mutation, retrieval and exact prompt inclusion | Authoritative live records or full specialist/prompt visibility |
| Gameplay recovery | Establish reliable completion and recovery before supporting unattended play | Supported persistence signals and interruption diagnostics |
| Examples and compiler | Broaden live coverage of composed patterns and generated worlds | Focused runtime acceptance checks; structural validation alone is insufficient |
| Permissions and video | Extend cross-account role coverage and specialist video behavior | Appropriate account roles and supported destination access |
| Platform changes | Maintain editor mappings, schema coverage and model guidance | New native exports and current editor/runtime evidence |

[Verified behavior](Verified-Behavior.md) records established results. [Known limits](Known-Limits.md) identifies unresolved behavior, and [Evidence](Evidence.md) explains how to distinguish documented features, runtime observations and optional patterns.
